# API MedPredict — контракт интеграции

GET/POST реализованы в [MedPredicts/backend](https://github.com/MedPredicts/backend/tree/3588c363e3d34946d86ce75be39a5695a8073176). Сверка и сквозная проверка с настоящим Spring Boot выполнены 21 октября 2026 года. Это готовая HTTP-интеграция; обученной модели в указанной версии backend ещё нет. Запуск, проверки и оставшиеся задачи: [integration.md](integration.md).

Фронтенд передаёт `Accept: application/json` и `Accept-Language: ru|kk|en` согласно выбранному языку. POST также передаёт `Content-Type: application/json`. Метаданные, их названия и успешный disclaimer остаются текстами провайдера, без автоматического перевода и подмены единиц.

## POST /api/v1/predictions

Поля запроса соответствуют `key` из GET; числовой ввод преобразуется в JSON number, select передаётся строкой, пустые необязательные поля не передаются. Для серверного demo:

```json
{
  "age": 52,
  "sex": "male",
  "bmi": 27.4,
  "totalCholesterol": 5.6,
  "glucose": 5.9
}
```

Успешный ответ (200):

```json
{
  "predictedValue": 134.2,
  "unit": "мм рт. ст.",
  "modelVersion": "demo-example",
  "disclaimer": "DEMO: фиксированный пример, не рассчитан по введённым данным. Не является диагнозом."
}
```

`predictedValue` — конечное число, `unit` — непустая строка, совпадающая с единицей GET. `modelVersion` и `disclaimer` необязательны; если присутствуют, должны быть непустыми строками. Ответы с неправильными типами или единицами не показываются как прогноз. Версия из GET не подставляется за отсутствующую версию ответа: результат должен относиться к фактически использованной модели. Постоянное предупреждение интерфейса не заменяется серверным.

`modelVersion: demo-example` — legacy-маркер фиксированного серверного примера. Интерфейс и PDF помечают такой результат как demo даже при `VITE_API_MODE=real`. Поля, единицы, HTTP-запрос и серверный disclaimer сохраняются. Обученному провайдеру нужна собственная версия.

GET и POST дополнительно поддерживают необязательные поля:

```json
{
  "predictionType": "estimated_current_measurement",
  "demo": false
}
```

При наличии `predictionType` разрешено только `estimated_current_measurement`, а `demo` должно быть булевым. `null`, строки вместо boolean и неподдерживаемые типы оценки отклоняются. Ответы старого сервера без этих полей продолжают работать. `demo: true` помечает любой фиксированный пример независимо от версии. Маркер `demo-example` также сохраняет предупреждение о демо; HTTP-режим `real` сам по себе не подтверждает наличие обученной модели.

`estimated_current_measurement` означает оценку текущего измеряемого показателя. Для модели САД это не фактическое измерение давления пациента и не прогноз на будущую дату. Результат и PDF содержат локализованные ограничения исследовательской модели: отсутствие сертификации, запрет клинической диагностики/лечения и изменения лекарств по оценке, необходимость измерения тонометром и отсутствие установленной применимости к населению Казахстана. Они не показывают категории риска, диагнозы, проценты «точности» или доверительные оценки для отдельного результата.

У обученной модели поле `glucose` означает **глюкозу плазмы натощак**, `totalCholesterol` — общий холестерин; оба в ммоль/л. Названия, подсказки, допустимые диапазоны и единицы поступают с GET и остаются данными провайдера. Интерфейс не подставляет локальные медицинские границы и не ограничивает динамическую схему пятью полями.

Ошибка валидации (400):

```json
{
  "error": "VALIDATION_ERROR",
  "fields": [
    { "field": "age", "message": "Возраст должен быть от 18 до 90 лет" }
  ]
}
```

Диапазон 18–90 в этом сообщении — пример из задания, **не согласованное ограничение текущей демоформы**. Текст валидного ответа связывается с известным полем; неизвестное имя вызывает общую ошибку контракта. Текст выводится через React без HTML-интерпретации. Некорректная структура ошибки валидации, не-JSON в успешном ответе или неожиданный 2xx — общая ошибка ответа. Сетевой сбой, таймаут и пользовательская отмена различаются.

| HTTP / error | Обработка фронтендом |
|---|---|
| `400 VALIDATION_ERROR` с `fields` | Связь ошибок с полями, фокус первого поля, ввод сохранён |
| `400 INVALID_REQUEST` с `message` | Общее сообщение об отклонённом запросе |
| `503 MODEL_UNAVAILABLE` с `message` | Явное сообщение о недоступной модели; при GET форма заблокирована |
| `500 SYSTEM_ERROR`, другие 5xx, в том числе HTML от proxy | Временная недоступность сервиса |
| Другие неуспешные JSON-ответы | Отклонённый запрос |

Произвольный `message` общих серверных ошибок не выводится: используются локализованные тексты интерфейса. Ошибки полей backend переводит по `Accept-Language`; уже полученный произвольный текст поля остаётся в языке того ответа.

## GET /api/v1/model/info

```json
{
  "indicatorName": "Систолическое давление — фиксированный DEMO-пример",
  "unit": "мм рт. ст.",
  "decimalPlaces": 1,
  "modelVersion": "demo-example",
  "fields": [
    { "key": "age", "label": "Возраст", "type": "number", "unit": "лет", "required": true },
    {
      "key": "sex", "label": "Пол", "type": "select", "required": true,
      "options": [
        { "value": "male", "label": "Мужской" },
        { "value": "female", "label": "Женский" }
      ]
    },
    { "key": "bmi", "label": "Индекс массы тела", "type": "number", "unit": "кг/м²", "required": true },
    { "key": "totalCholesterol", "label": "Общий холестерин", "type": "number", "unit": "ммоль/л", "required": true },
    { "key": "glucose", "label": "Глюкоза", "type": "number", "unit": "ммоль/л", "required": true }
  ]
}
```

Все поля верхнего уровня обязательны, кроме `modelVersion`, `predictionType` и `demo`. `decimalPlaces` — целое от 0 до 20 (технический предел отображения) или явно `null` для сохранения исходной точности. Значение 1 в примере — только демонстрационная настройка, не утверждённая точность модели.

`fields` — непустой массив с уникальными `key`. Разрешённые имена: латинская буква, затем латинские буквы, цифры или `_`; `constructor`, `prototype`, `__proto__` запрещены. Порядок массива определяет порядок формы. У каждого поля обязательны `key`, `label`, `type`, `required`; необязательна непустая строка `hint`.

- `number`: обязательна `unit`; необязательны конечные `min`, `max`, булево `integer`. min не больше max. Без этих параметров нет медицинских ограничений.
- `select`: обязательны непустые `options` с уникальными непустыми `value` и непустыми `label`.

Новые числовые/списковые показатели не требуют менять компоненты: форма и payload строятся по GET. Другие типы полей потребуют согласованного расширения. Если описание отсутствует/невалидно, ввод и POST недоступны: интерфейс предлагает повторить GET.

## Поведение и приватность

Базовый origin берётся из `VITE_API_BASE_URL`; путь `/api/v1` уже входит в endpoints. Пустой origin использует origin сайта. При локальной разработке Vite направляет `/api` на `API_PROXY_TARGET` (по умолчанию `http://127.0.0.1:8080`). Production требует reverse proxy `/api` к backend либо явного HTTPS origin API с CORS. Таймаут действует на запрос и чтение тела ответа. `AbortController` обеспечивает отмену, изменение ввода, размонтирование; идентичность запроса дополнительно блокирует запоздалые результаты. Одновременно выполняется максимум один POST. Автоматических повторов и переключения в демо нет.

Реальный режим передаёт только показатели на настроенный сервер. Нет localStorage/sessionStorage, аналитики, логирования формы, URL-параметров с показателями. Заголовки и сообщения не содержат ключей или медицинских значений. Настройка окружения публична, секреты в ней недопустимы.

## Что согласовать с командой

| Вопрос | Ответственный |
|---|---|
| Окончательный показатель, набор признаков и единицы | Али + Оралхан + команда |
| min/max, целочисленность, обязательность, варианты пола из датасета | Али, затем серверная валидация Оралхана |
| Методология и точность отображения | Али |
| Изменения реализованного GET/POST, согласованность единиц и версий реальной модели | Оралхан + Санат |
| CORS, URL окружений, HTTPS, таймауты и эксплуатация | Оралхан |
| Хранение и логи сервера, обработка медицинских данных | Оралхан + команда |
| Локализация названий полей на казахский | Санат + команда |

Нельзя выводить из этого примера клиническую точность, категорию здоровья, вероятность болезни или доверительные интервалы. Сервер остаётся источником окончательной валидации.

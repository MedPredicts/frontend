# Интеграция frontend, backend и модели

Рабочий срез: 21 октября 2026 года. Контракт: [api-contract.md](api-contract.md). Обучение, данные и воспроизводимые эксперименты находятся в [ML workspace](../ml/README.md); результаты и ограничения — в `docs/ml/`.

Исходная HTTP-интеграция была проверена с [backend `3588c36`](https://github.com/MedPredicts/backend/tree/3588c363e3d34946d86ce75be39a5695a8073176). Описанные ниже изменения для ONNX разрабатываются локально; их наличие в опубликованной ветке GitHub нельзя выводить из этого документа.

## Поведение приложения

- GET `/api/v1/model/info` задаёт названия, порядок, единицы и допустимые диапазоны полей. POST `/api/v1/predictions` принимает плоский JSON. Форма не подставляет собственные медицинские границы.
- Для модели текущего САД нужны возраст, пол, ИМТ, общий холестерин и **глюкоза плазмы натощак**. Оба лабораторных показателя передаются в ммоль/л. Сервер остаётся источником точной схемы.
- Число в результате — **экспериментальная оценка текущего систолического давления**, а не фактическое измерение пациента и не прогноз будущего давления. Интерфейс и PDF показывают это пояснение, версию модели и исследовательские ограничения.
- `predictionType: estimated_current_measurement`, `demo: false` описывают обученный провайдер. `demo: true` явно отмечает фиксированный пример независимо от версии. Старый `modelVersion: demo-example` также распознаётся как demo. HTTP-режим `real` сам по себе не означает наличие модели.
- Полные ограничения для обученной модели локализованы на русском, казахском и английском: модель не сертифицирована, не предназначена для диагностики/лечения, не заменяет тонометр, не должна использоваться для изменения лекарств; качество на NHANES не подтверждает применимость к населению Казахстана. Категорий риска, диагноза и «процента точности» в результате нет.
- Loading, явная отмена, повтор, сохранение ввода при ошибке, связь ошибок с полями, клавиатурный фокус и защита от устаревших ответов сохранены. Нет автоматического перехода в demo при сбое.

Названия полей, единицы, indicatorName и дополнительный disclaimer являются данными провайдера и сохраняются в языке ответа. Собственные тексты интерфейса меняются на ru/kk/en без потери формы и результата. PDF использует уже полученный ответ, без повторного inference.

## Локальный запуск ONNX

Нужны JDK 17+, Node.js 22.12+, npm и обученные артефакты. Backend использует Maven wrapper. Подготовку модели выполняйте по `ml/README.md`; один включённый HTTP-режим не создаёт артефакты.

Терминал backend (в каталоге backend с новой ONNX-интеграцией):

```sh
MEDPREDICT_MODEL_DIRECTORY=/Users/admin/MedPredict/ml/artifacts \
PORT=8081 \
CORS_ALLOWED_ORIGINS=http://127.0.0.1:5173,http://127.0.0.1:5175 \
bash ./mvnw spring-boot:run -Dspring-boot.run.profiles=onnx
```

Терминал frontend:

```sh
npm ci
API_PROXY_TARGET=http://127.0.0.1:8081 npm run dev
```

Открыть landing [127.0.0.1:5173](http://127.0.0.1:5173), затем нажать «Получить оценку» для перехода к `#/predict`. Карточка 134,2 на landing — подписанный фиксированный пример; фактический результат модели появляется после отправки формы. Чтобы сохранить target, можно создать `.env.local` по `.env.example`, задать `API_PROXY_TARGET` и перезапустить Vite. Не добавляйте `/api/v1` в target: путь уже входит в запросы.

Backend ONNX должен загрузить артефакты и проверить их версию. `/api/v1/health/live` сообщает о процессе; `/api/v1/health/ready` и `/api/v1/model/status` — о готовности модели. При отсутствии или повреждении модели сервер должен возвращать явную недоступность, без фиксированного числового fallback. Default без профиля сохраняет `503 MODEL_UNAVAILABLE`.

Синтетический пример для проверки интерфейса: возраст `52`, пол `male`, ИМТ `27,4`, холестерин `5,6`, глюкоза натощак `5,9`. Ожидаемое числовое значение берётся из фактического inference, а не задаётся в UI-тесте.

### Отдельный серверный demo

```sh
bash ./mvnw spring-boot:run -Dspring-boot.run.profiles=demo
```

Он работает на 8080 по умолчанию. Обычный `npm run dev` проксирует `/api` на этот адрес. Фиксированное `134,2 мм рт. ст.` явно помечается как демонстрационный пример, не рассчитанный по введённым данным.

### Автономная демонстрация

```sh
npm run dev:demo
# Отдельная demo-сборка:
npm run build:demo
npm run preview
```

Она не передаёт показатели серверу. Локальные `.env.local` и переменные процесса имеют приоритет над `.env.demo`; проверяйте подпись режима. Сценарий задаётся `VITE_DEMO_SCENARIO=success|validation|unavailable`.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run build:demo
npm run test:e2e
# Настоящий backend demo на8080; порт5173 должен быть свободен:
npm run test:integration
# Настоящий backend onnx на8081; отдельный временный frontend на5175:
npm run test:integration:model
```

`test:e2e` запускает синтетические HTTP-ответы на 4173/4174 и автономный demo. `test:integration` проверяет настоящий server demo. `test:integration:model` обращается к реальному ONNX-backend: readiness → metadata → форма → POST → отображение фактического ответа → казахские ограничения → PDF. Отдельный сценарий меняет только синтетический request, чтобы проверить настоящую серверную валидацию, фокус, сохранение ввода и повтор. Ответы сервера в этих сквозных тестах не подменяются.

Viewports интеграции: 1440×1100 и 390×844. PDF и результаты сквозных тестов сохраняются в системных временных каталогах `medpredict-integration-results` и `medpredict-model-integration-results`. Скриншоты результата модели — в `/private/tmp/medpredict-real-model-backend-desktop.png` и `/private/tmp/medpredict-real-model-backend-mobile.png`.

В текущем frontend-срезе выполнены typecheck, lint, 93 unit/PDF-теста, обе сборки, 46 Playwright-тестов desktop/mobile, 4 сценария с настоящим server demo и 4 сценария с настоящим ONNX-backend8081. Server demo проверен через временные порты frontend5176/backend8082, ONNX — через frontend5175/backend8081. Пользовательский сервер5173 сохранён; оригинальный demo integration config не менялся. Проверены семантика оценки, явное demo с новой версией, API-ошибки, смена языка, фокус, отсутствие storage, PDF, отсутствие горизонтального переполнения и ошибок console в новом успешном сценарии. Browser plugin в сессии отсутствовал; использован установленный Playwright/Chromium. Скриншоты desktop/mobile просмотрены. Предупреждение `NO_COLOR/FORCE_COLOR` относится к Node-окружению.

## Production и ограничения

`npm run build` собирает HTTP-версию. Размещение требует reverse proxy `/api` к Spring Boot либо `VITE_API_BASE_URL=https://<адрес-api>` перед сборкой и точного origin сайта в backend `CORS_ALLOWED_ORIGINS`. Vite proxy работает только при разработке. `VITE_*` публичны и не должны содержать секреты.

HTTPS, запрет записи медицинского body в access/APM/debug-логи, управление артефактами и их доступностью проверяются на окружении размещения. Публичный адрес API не задан; публикация в этот этап не входит.

Фронтенд не пишет показатели в localStorage/sessionStorage, URL, аналитику или логи. Пользовательский PDF содержит экспортированные им значения. Клиническая применимость и работа на населении Казахстана требуют отдельной проверки; held-out эксперимент NHANES не является клинической валидацией. История пациентов и аутентификация в этот сценарий не добавлены.

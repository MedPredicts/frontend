# MedPredict frontend

Фронтенд учебного проекта по прогнозированию медицинских показателей. React + TypeScript + Vite, интерфейс на казахском, русском и английском языках, проверка данных, API-адаптер и экспорт в PDF.

Одностраничный интерфейс подключён к [MedPredicts/backend](https://github.com/MedPredicts/backend) через HTTP. Расширенный интерфейс по макету Figma будет добавлен отдельно. Серверный профиль `demo` возвращает фиксированный пример; обученная модель пока не подключена. Полные инструкции запуска и оставшиеся задачи: [отчёт интеграции](docs/integration.md).

## Запуск

Нужны Node.js 22.12+, npm и JDK 17+ для бэкенда.

Сначала в репозитории бэкенда запустите сервер:

```sh
bash ./mvnw spring-boot:run -Dspring-boot.run.profiles=demo
```

В другом терминале запустите фронтенд:

```sh
git clone https://github.com/MedPredicts/frontend.git
cd frontend
npm ci
npm run dev
```

Адрес бэкенда — [127.0.0.1:8080](http://127.0.0.1:8080), фронтенда — [127.0.0.1:5173](http://127.0.0.1:5173). Файл `.env.development` включает HTTP-режим; Vite направляет запросы `/api` на бэкенд. Серверное демо всегда возвращает `134,2` независимо от ввода и явно помечается в интерфейсе и PDF. Без профиля `demo` текущий бэкенд возвращает `503 MODEL_UNAVAILABLE`.

## Автономное демо

Для запуска без бэкенда или подготовки демонстрационной сборки:

```sh
npm run dev:demo
# Или:
npm run build:demo
npm run preview
```

Автономное демо не отправляет запросы прогноза серверу. Результат — фиксированный пример, который не рассчитывается по введённым данным. Доступные сценарии: `success`, `validation`, `unavailable`.

## Интеграция с API

`GET /api/v1/model/info` и `POST /api/v1/predictions` проверены с сервером Spring Boot. Форма строится по описанию полей от сервера; язык ошибок передаётся через `Accept-Language`. Обрабатываются серверная валидация, таймаут, отмена и повтор запроса. Полные форматы: [контракт API](docs/api-contract.md).

Команда `npm run build` создаёт HTTP-версию. При размещении настройте обратный прокси `/api` к бэкенду либо укажите HTTPS-адрес в `VITE_API_BASE_URL` и добавьте origin сайта в `CORS_ALLOWED_ORIGINS` на бэкенде. Для реального прогноза ещё нужны обученная модель, предобработка данных и контрольные примеры её работы.

`.env.example` — шаблон локальных настроек. Переменные `VITE_*` попадают в браузерный код, поэтому не записывайте в них секреты. Ошибка в режиме `real` не переключает приложение в демо автоматически.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
# Бэкенд должен работать с профилем demo на порту 8080:
npm run test:integration
```

E2E-тесты используют синтетические примеры и подмену ответов API. Временные серверы работают на портах 4173 и 4174. Команда `test:integration` проверяет настоящий Spring Boot на компьютере и мобильном размере экрана: описание полей → форма → POST → маркированный результат → PDF. Также проверяются серверная ошибка и успешный повтор. Порт фронтенда — 5173.

## Структура

- `src/` — страница, компоненты, проверка ввода, API, переводы и PDF.
- `public/` — логотипы, флаги и локальные шрифты.
- `tests/` — сценарии Playwright.
- `docs/api-contract.md` — реализованный контракт API.
- `docs/integration.md` — запуск, результаты проверок и оставшиеся задачи.
- `docs/design/icons.md` — цвета, иконки и источники ресурсов.

Показатели хранятся только в текущем состоянии React; они не записываются в `localStorage`, `sessionStorage`, аналитику или логи фронтенда. PDF содержит данные, которые пользователь экспортировал самостоятельно.

Шрифт Noto Sans распространяется по [лицензии OFL](public/fonts/OFL.txt). Иконки — [Flaticon Uicons](docs/design/icons.md).

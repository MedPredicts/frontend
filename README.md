## О проекте

MedPredict — дипломный проект студентов **Astana IT University**. Этот репозиторий содержит React frontend и воспроизводимый ML-эксперимент; Spring Boot находится в отдельном [репозитории backend](https://github.com/MedPredicts/backend).

**Локальная интеграция на 21 октября 2026:** обучена собственная **MedPredict-SBP-mlp-v2** на CDC NHANES, экспортирована в ONNX и подключена к Spring Boot. Проверены Python/ONNX/Java; исправления backend сохранены отдельным [патчем и инструкцией](ml/integration/README.md). Эти новые изменения ещё не опубликованы в GitHub. [Запуск приложения и проверки](docs/integration.md), [обучение и воспроизведение](ml/README.md), [результаты](docs/ml/experiment-results.md), [model card](docs/ml/model-card.md).

Знакомство → ввод → проверка → отправка → результат. Ввод хранится только в памяти вкладки; в HTTP-режиме отправляется настроенному backend.

**Текущий статус — исследовательский прототип.** Модель оценивает текущее измеренное систолическое давление по возрасту, полу, ИМТ, общему холестерину и глюкозе плазмы натощак. Она не прогнозирует будущее давление. На 497 тестовых участниках взвешенная MAE — **11,23 мм рт. ст.**, обычная MAE — **12,40**. Высокое давление существенно недооценивается; модель не предназначена для диагностики, лечения или изменения лекарств и не заменяет тонометр. Применимость к Казахстану не проверена. Отдельный demo возвращает фиксированные **134,2 мм рт. ст.** и явно помечается.

Проблема проекта — воспроизводимо связать описание признаков, проверку ввода, ответ модели и его ограничения. Предполагаемые пользователи — исследователи и участники учебной демонстрации; потребность ещё требует подтверждения обсуждениями. Ожидаемый результат — интегрированный прототип и сравнение модели с простыми базовыми решениями на независимых данных. Диагностика и рекомендации по лечению в границы проекта не входят. Полная постановка: [предложение по проекту](docs/project-proposal.md).

Официальная тема — «Разработка интеллектуальной системы прогнозирования медицинских показателей на основе нейронных сетей». В историческом комплекте предложены три независимых модуля: числовой target Diabetes, оценка измеренного САД на NHANES и краткосрочный прогноз глюкозы на ещё не выбранном продольном наборе PhysioNet. ## Быстрый запуск

Нужны **Node.js 22.12+** и **npm**.

```sh
git clone https://github.com/MedPredicts/frontend.git
cd frontend
npm ci
npm run dev
```

Сначала запустите backend на `8080` с явным профилем `demo`: `bash ./mvnw spring-boot:run -Dspring-boot.run.profiles=demo`. Затем откройте **[127.0.0.1:5173](http://127.0.0.1:5173)**. Обычный запуск использует HTTP через Vite proxy. Для автономного frontend-примера: `npm run dev:demo`. Нажмите **«Перейти к форме»**; форма изначально пустая.

Синтетические данные для демонстрации:

| Возраст | Пол | ИМТ | Общий холестерин | Глюкоза |
|---|---|---|---|---|
| 52 | Мужской | 27,4 | 5,6 | 5,9 |

В demo нет согласованных медицинских диапазонов: технически допустимый ввод не означает медицинскую корректность.

## Работа с API

Для собственной конфигурации скопируйте шаблон:

```sh
cp .env.example .env.local
```

| Переменная | Назначение |
|---|---|
| `VITE_API_MODE` | `demo` или `real`; обязательна |
| `VITE_DEMO_SCENARIO` | `success`, `validation` или `unavailable`; обязательна в demo |
| `VITE_API_BASE_URL` | Origin сервера; пустое значение использует origin сайта |
| `VITE_API_TIMEOUT_MS` | Таймаут API; по умолчанию `15000` мс |
| `API_PROXY_TARGET` | Адрес backend для локального Vite proxy; по умолчанию `http://127.0.0.1:8080` |

После изменения `.env.local` перезапустите Vite. `VITE_*` попадает в браузерный код — не используйте эти переменные для секретов.

<details>
<summary><strong>Демонстрационные сценарии</strong></summary>

```dotenv
VITE_API_MODE=demo
VITE_DEMO_SCENARIO=success
```

- `success` — фиксированный пример результата.
- `validation` — фиксированная ошибка возраста независимо от ввода; это тест интерфейса, а не медицинская проверка.
- `unavailable` — сценарий недоступного сервиса.

Demo не отправляет показатели сетевыми запросами и не обращается к модели.

</details>

<details>
<summary><strong>Подключение Java / Spring Boot</strong></summary>

```dotenv
VITE_API_MODE=real
VITE_API_BASE_URL=http://localhost:8080
VITE_API_TIMEOUT_MS=15000
```

| Запрос | Назначение |
|---|---|
| `GET /api/v1/model/info` | Описание показателя, полей, единиц, точности и ограничений |
| `POST /api/v1/predictions` | Отправка проверенных значений и получение результата |

GET/POST реализованы backend и проверены через HTTP. Полный формат запросов, ответов и ошибок — в [контракте API](docs/api-contract.md). По умолчанию `.env.development` и `.env.production` используют HTTP; production требует reverse proxy `/api` к backend либо отдельного API origin с CORS.

Без валидного описания модели форма и POST недоступны. Ошибка real не переключает приложение в demo; автоматических повторов POST нет. `real` обозначает HTTP-подключение: серверный профиль `demo` возвращает помеченный фиксированный пример; профиль `onnx` с проверенным bundle возвращает обученную оценку. Без профиля или при отсутствии модели backend возвращает `503 MODEL_UNAVAILABLE`. Auth и история отсутствуют в текущем API.

Поля, единицы и ограничения задаёт сервер. У модели NHANES min/max отражают область обучения, а не медицинские нормы. `decimalPlaces: null` сохраняет точность полученного числа; min/max/integer применяются только при наличии в конфигурации. Ошибки полей переводятся backend по `Accept-Language`; metadata и дополнительный server disclaimer показываются как получены. Объяснение исследовательской оценки и основное предупреждение переведены на три языка.

</details>

## PDF и приватность

После успешного ответа кнопка **«Скачать PDF»** формирует текстовый A4 с логотипами, датой документа, показателем, отправленными значениями и единицами, результатом, версией ответа и предупреждениями. Demo помечен как фиксированный пример, обученный ответ — как исследовательская оценка текущего САД. Дата документа не подменяет время измерения или оценки.

Экспорт использует снимок проверенного запроса и существующий ответ, без повторного POST и диалога печати. Подготовка блокирует повторный экспорт; ошибка позволяет попробовать снова. Изменение данных, уход с результата и смена языка отменяют незавершённый экспорт. Папку сохранения определяет браузер.

- Показатели и язык хранятся только в памяти React. Перезагрузка или закрытие вкладки очищает ввод.
- Нет хранения показателей в `localStorage`, `sessionStorage`, аналитике или frontend-логах; данные не помещаются в URL.
- Real отправляет значения только настроенному серверу. Политику хранения и логирования на сервере определяет backend-команда.
- PDF содержит экспортированные пользователем показатели. Шрифт Noto Sans и логотипы загружаются локально; кириллица и казахские буквы поддерживаются.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npx playwright install chromium  # один раз, если браузер ещё не установлен
npm run test:e2e
# При запущенном backend demo на 8080:
npm run test:integration
# При запущенном backend onnx на 8081:
npm run test:integration:model
```

E2E используют два временных Vite-сервера на `4173` и `4174`, desktop `1440×1200` и mobile `390×844`; проверки узких экранов включают `320 px`. В real-сценариях ответы API подменяются, поэтому Spring Boot для этих тестов не нужен. Все примеры синтетические.

`test:integration` отдельно проверяет настоящий Spring Boot demo через frontend на `5173`; `test:integration:model` использует временный frontend `5175` и настоящий ONNX backend `8081`, без подмены ответов, в desktop/mobile. Подробности: [отчёт интеграции](docs/integration.md).

Исторические проверки: [docs/verification.md](docs/verification.md). Актуальные проверки обученной модели и приложения: [docs/integration.md](docs/integration.md) и [ML-отчёты](ml/reports/).

<details>
<summary><strong>Сборка и локальный preview</strong></summary>

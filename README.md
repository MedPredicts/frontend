# MedPredict — frontend

Учебный исследовательский прототип студентов Astana IT University: **оценка текущего систолического давления** по пяти исходным показателям. React, TypeScript, Vite; интерфейс на казахском, русском и английском.

## Проблема целевые пользователи и ожидаемые результаты

При переносе исследовательской ML-модели в приложение можно потерять смысл результата: перепутать единицы и порядок признаков, оценку текущего показателя и будущий прогноз либо фиксированный demo и обученный inference. MedPredict решает инженерную задачу согласования данных, модели, HTTP-контракта и понятного интерфейса, сохраняя ограничения проведённого эксперимента.

**Целевые пользователи:** студенты медицинских и технических специальностей, исследователи и участники учебных демонстраций, изучающие работу моделей медицинских показателей. Прототип не предназначен для принятия решений о лечении пациентов.

**Ожидаемый результат frontend:** адаптивный интерфейс RU/KK/EN с вводом и проверкой показателей, понятным состоянием запроса, показом результата с версией и ограничениями, а также PDF-экспортом. Ожидаемый результат проекта в целом — сравнение нейросети с базовыми методами, проверяемая интеграция и документация воспроизведения. Что уже реализовано и что ещё не опубликовано, перечислено ниже; преимущество нейросети заранее не предполагается.

## Состояние на 24 октября 2026 года

Frontend поддерживает автономный фиксированный demo и HTTP-подключение к backend. Проверенные исходные срезы: frontend `7eddeffd` (PR №3), backend `3588c363`; последующие коммиты README и диаграмм не меняют этот код. Этот backend содержит unavailable/demo-провайдеры, без ONNX inference и model-readiness endpoints. Поэтому клонирование текущих опубликованных репозиториев позволяет показать demo и HTTP-контракт, но не готовую связку с обученной моделью.

## Что работает

- Landing на `/`, переход к рабочей форме через «Получить оценку» на `#/predict`.
- Динамическая схема полей из backend: возраст, пол, ИМТ, общий холестерин и **глюкоза плазмы натощак**. Оба лабораторных показателя — в ммоль/л.
- Клиентская и серверная валидация, связанные с полями ошибки, loading, отмена, повтор и защита от устаревших ответов.
- Отображение результата с единицей, версией и ограничениями; различение фиксированного demo и обученной модели.
- Текстовый PDF с отправленными значениями и уже полученным результатом, без повторного запроса модели.
- Адаптивность desktop/mobile, клавиатурная навигация и видимый фокус.

Вход, регистрация и история показаны как недоступные действия: соответствующий серверный API и хранение пациентов не реализованы. Карточка `134,2` на landing — подписанный фиксированный пример. После отправки формы выводится ответ активного провайдера: в demo это такой же фиксированный пример; обученная оценка возможна только с отдельно предоставленной совместимой ONNX-интеграцией.

## Модель и границы применения

**MedPredict-SBP-mlp-v2** обучена на открытых измерениях CDC NHANES 2017–March 2020. Это оценка текущего измеряемого САД, а не фактическое измерение пациента, прогноз будущего давления, диагноз или риск заболевания.

После отбора осталось 3 318 участников; train/validation/test — 2 324 / 497 / 497. Взвешенная test-MAE модели — **11,23 мм рт. ст.**, обычная MAE — **12,40 мм рт. ст.** Средняя ошибка не является интервалом для отдельного результата. При высоком САД ошибки особенно велики и значения существенно занижаются. Подробности локального M2: [ML-AI README](https://github.com/MedPredicts/ml-ai#readme) и [итоговый отчёт](https://github.com/MedPredicts/documentation/blob/main/report/MedPredict_Project_Report_24_October_2026.pdf).

Прототип не сертифицирован, не предназначен для диагностики, лечения или изменения лекарств и не заменяет тонометр. Применимость к населению Казахстана не проверена. Границы полей отражают область обучения, а не медицинские нормы. Временные ряды, будущий прогноз давления и другие модели остаются за границами этой версии.

## Запуск опубликованного backend в явном demo

Для HTTP-сценария нужны Git, JDK 17+ и доступ к Maven-зависимостям. Модель или Python для фиксированного demo не нужны:

```sh
git clone https://github.com/MedPredicts/backend.git
cd backend
sh ./mvnw spring-boot:run -Dspring-boot.run.profiles=demo
```

API работает на `8080`. [GET model/info](http://127.0.0.1:8080/api/v1/model/info) возвращает demo-метаданные; POST `/api/v1/predictions` — фиксированные `134,2 мм рт. ст.`, `modelVersion: demo-example` и предупреждение независимо от синтетического ввода. [Swagger UI](http://127.0.0.1:8080/swagger-ui/index.html) показывает контракт. Профиль `demo` не является обученным inference.

Без профиля этот backend возвращает `503 MODEL_UNAVAILABLE`. В его проверенном текущем срезе нет `/health/ready`, ONNX-провайдера и настройки загрузки bundle: профиль `onnx` или переменная `MEDPREDICT_MODEL_DIRECTORY` сами по себе модель не подключают. Устройство сервера и команды тестирования — в [backend README](https://github.com/MedPredicts/backend#readme).

### Отдельная локальная ONNX-интеграция

Для обученного M2 нужны совместимый серверный исходный срез с ONNX-провайдером и проверенный bundle `model.onnx` + `metadata.json`. Они были проверены в отдельной локальной интеграции, но их готовый запуск из текущих опубликованных `main` не подтверждён. [ML-AI README](https://github.com/MedPredicts/ml-ai#readme) описывает результаты и статус публикации. [docs/integration.md](docs/integration.md) сохраняет протокол и результаты 21 октября; его старые clone-ссылки и утверждения о remote `main` следует читать как историческую запись, а не действующий quick start. Для текущей демонстрации используйте команды demo выше.

## Запуск frontend

В другом терминале; нужны Git, Node.js 22.12+ и npm. Для HTTP-сценария сначала запустите backend demo по инструкции выше:

```sh
git clone https://github.com/MedPredicts/frontend.git
cd frontend
npm ci
npm run dev
```

Открыть [127.0.0.1:5173](http://127.0.0.1:5173), затем перейти к форме. Vite направляет `/api` на backend `http://127.0.0.1:8080`; в этом сценарии ответ остаётся фиксированным серверным demo.

Для автономного фиксированного примера без backend: `npm run dev:demo`. Он не выполняет обученный inference и не отправляет показатели серверу.

Если нужен другой адрес, скопируйте [`.env.example`](.env.example) в `.env.local` и перезапустите Vite:

| Переменная | Назначение |
|---|---|
| `VITE_API_MODE` | `real` — HTTP; `demo` — автономный фиксированный пример |
| `API_PROXY_TARGET` | Backend для локального Vite proxy, по умолчанию `http://127.0.0.1:8080` |
| `VITE_API_BASE_URL` | Пусто — origin сайта; отдельный API origin требует CORS |
| `VITE_API_TIMEOUT_MS` | Таймаут запросов, по умолчанию 15 000 мс |
| `VITE_DEMO_SCENARIO` | Только для demo: `success`, `validation`, `unavailable` |

`real` обозначает HTTP-подключение: профиль backend определяет, обученная модель это или серверный demo. `VITE_*` публичны — секреты в них недопустимы. Production требует HTTPS и reverse proxy `/api` либо отдельного origin API с CORS. Подробнее: [интеграция](docs/integration.md) и [контракт API](docs/api-contract.md).

## Приватность

Показатели находятся в памяти вкладки и в HTTP-режиме передаются настроенному серверу. Frontend не записывает их в localStorage/sessionStorage, URL, аналитику или логи. Backend не сохраняет прогнозы и не логирует body. После перезагрузки вкладки ввод очищается. Экспортированный пользователем PDF содержит введённые значения; логирование и доступ на окружении размещения требуют отдельной настройки.

Названия полей, единицы и дополнительное предупреждение модели показываются в языке ответа API; сейчас это русский. Собственные тексты интерфейса, ошибки клиента и основное исследовательское предупреждение переведены на ru/kk/en.
